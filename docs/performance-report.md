### 分析

- Release 比 Debug 平均提升约 25%（~10% → ~7.5%），但**未达到 <2% 目标**。

- 采样波动较大（5.3% ↔ 10.4%），疑似周期性 IOKit 调用（GPU 1s + SMC 10 key × 2 次调用）瞬时拉高，与 Phase 2 模块化刷新间隔的预期收益一致。

## 分析

### CPU 占用

Debug 构建不开启编译器优化（`-O0`），所有函数调用、内存访问均为未优化路径。Release 构建（`-Osize`）通常有 3-5 倍性能提升，预计 CPU 可降至 **2-4%**。

| 采集模块 | 刷新频率 | 估计开销 | 优化方案 |
|---------|:---:|:---:|------|
| CPU（host_processor_info） | 1s | ~2% | 保持 |
| 内存（host_statistics64） | 1s | ~1% | 降至 2s |
| 网络（getifaddrs） | 1s | ~1% | 保持 |
| GPU（IOAccelerator） | 1s | ~1% | 降至 2s |
| SMC 温度（IOConnectCallStructMethod） | 1s | ~1% | 降至 5s |
| SwiftUI 视图更新 | 1s | ~2% | 减少 @Published 粒度 |

最优方案：推进 Phase 2 模块化刷新间隔，GPU/温度等低频需求降低刷新率。

### 内存占用

107 MB RSS 中约 60-70 MB 为 Swift 运行时 + SwiftUI + AppKit 框架加载，不可压缩。实际业务数据（SystemStats + NetworkHistory + SMC/SMCBytes 结构体）约 5-10 MB。Debug 构建的符号表和调试信息也会驻留内存。

Release 构建预计降至 **40-50 MB**，接近或达到 <50 MB 目标。

### 内存泄漏

60 秒内 RSS 在 107.0–107.1 MB 之间波动，偏差 <0.1%，无持续增长趋势，**确认无内存泄漏**。

### 稳定性

- 系统日志无错误（仅无关的 CoreSpotlight / XPC 系统消息）
- 无崩溃报告
- 弹窗展开/收起后尺寸恢复正常
